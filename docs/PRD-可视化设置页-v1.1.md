## 二、背景与目标

### 2.1 背景

- DLsiteFloat（`io.github.ariinyume.dlsitesoundfloat`，当前 v2.1.2 / code 954 / label `0926.3`）是作用于 DLsiteSound（`jp.co.eisys.dlsitesound`）与 SystemUI 的 LSPosed 悬浮字幕插件。
- **现状痛点**：字幕外观（颜色、阴影、缩放、模糊、排版等）全部硬编码在 hook 代码中（如 `StatusBarSubtitleHook` 中 `0xFFFFFFFF` 等常量），用户无法调整；每次微调都要改码、打包含验证，成本高且只有开发者能用。
- 竞品/同域参考：ColorOS-Live-Lyrics-Bridge 已验证「模块自带 Material 3 设置页 + 实时预览 + 显式 Apply and save + 配置备份恢复」的交互模型在 Xposed 字幕类插件上体验良好。

### 2.2 要解决的问题

1. 用户（含非开发者）可以不改码调整悬浮字幕外观；
2. 调整过程所见即所得，避免「改完重启才发现不好看」；
3. 配置可保存、可恢复、可迁移（换机/重装不丢）。

### 2.3 成功指标与口径

| 指标       | 口径                        | 目标值                |
| -------- | ------------------------- | ------------------ |
| 设置覆盖率    | 提供设置项的字幕外观属性数 ÷ 硬编码外观属性总数 | ≥ 90%（本期目标清单见 §10） |
| 预览一致性    | 预览区渲染结果与真实悬浮窗的参数级差异       | 零参数偏差（允许像素级抗锯齿差异）  |
| 保存生效     | 点击「保存设置」后配置落盘成功率          | 100%（失败必须给明确报错）    |
| 调整耗时（估算） | 从打开设置页到完成一次「改色 + 保存」的操作步数 | ≤ 5 步关键操作          |

## 三、名词与术语定义

| 术语                                | 定义                                                                     |
| --------------------------------- | ---------------------------------------------------------------------- |
| 活动行                               | 当前正在显示的字幕行（高亮、放大、最亮的那一行）                                               |
| 非活动行                              | 已播放过或未播放到的字幕行（默认弱化显示）                                                  |
| 预览草稿态                             | 用户改动尚末「保存设置」的状态；只影响预览区，不影响真实悬浮窗                                        |
| 已保存态                              | 点击「保存设置」后，配置已写入标准配置文件的状态                                               |
| 标准配置                              | 插件约定的字幕配置文件（键表见 §10），设置页与 SystemUI hook 共同的唯一事实源                       |
| SystemUI 重启                       | 杀死并重建 `com.android.systemui` 进程，使 hook 侧重新初始化                          |
| MD3                               | Material Design 3 设计语言（动态取色、色槽、圆角卡片、 segmented button、slider、switch 等） |
| primaryContainer / errorContainer | MD3 颜色色槽名，分别用于「成功/激活」与「错误/未激活」语义底色                                     |
| 色槽                                | MD3 中预定义的颜色角色（如 onPrimaryContainer、outline 等）                          |

## 四、需求范围

### 4.1 包含（本期）

1. 设置页整体信息架构与 MD3 视觉规范（两屏长页 + 吸底操作栏 + 吸顶预览）；
2. 模块激活状态卡（含 SystemUI 授权状态分立展示、语言切换按钮）；
3. 调整预览窗（用户桌面壁纸 + 悬浮窗示意 + 示例字幕，拖动实时重绘、吸顶跟随）；
4. 主字幕 / 活动行调整组：颜色、阴影颜色、阴影强度、阴影半径、主字幕高亮、主字幕放大倍数、恢复默认；
5. 非活动行字幕调整组：模糊开关与半径、缩放开关与比例、恢复默认；
6. 字幕排版组：字重、对齐、字幕间行距、长字幕内换行额外行距、恢复默认；
7. 其他组：状态栏字幕开关、字幕配置备份与恢复（导出/恢复）、悬浮窗字幕显示时保持屏幕常亮；
8. 吸底操作栏：重启系统界面（带二次确认）、保存设置（写入标准配置并使悬浮窗刷新）；
9. 设置页三语 i18n：简体中文 / 繁體中文 / English；
10. 配置文件 Schema（键名、类型、范围、默认值、版本号）与设置页 → SystemUI 的配置传递方案。

### 4.2 不包含（本期不做）

| 项                                    | 说明                                                   | 去向       |
| ------------------------------------ | ---------------------------------------------------- | -------- |
| 字幕预设主题（Default/Soft/Vivid/Minimal 式） | 参考项目有，但本期先把参数面板做扎实                                   | 后续版本     |
| 逐词高亮 / 歌词时间轴编辑                       | DLsiteSound 字幕源为整句 cue，无逐词数据                         | 不做（场景不符） |
| 在 DLsiteSound App 内的插件界面多语言          | 语言切换只作用于设置页 UI 与预览区示例字幕（见 FR-02），不改 DLsiteSound 本体语言 | 明确不做     |
| 设置页深色主题的独立定制                         | 跟随系统 MD3 动态深浅色，不做手动模式选择                              | 跟随系统     |
| 配置云同步                                | 仅本机导出/导入                                             | 明确不做     |

## 五、方案对比与选型说明

### 5.1 候选方案

| 维度    | 方案 A：独立设置 Activity + MD3 原生控件 + 配置文件中转（推荐） | 方案 B：设置页做成悬浮窗内嵌面板          | 方案 C：沿用 LSPosed「无 UI + 改配置文件手编」 |
| ----- | ------------------------------------------ | -------------------------- | ------------------------------- |
| 实现成本  | 中（新增 MainActivity + 预览控件 + 配置读写层）          | 高（SystemUI 进程内做交互面板，事件冲突多） | 低                               |
| 开发复杂度 | 中                                          | 高                          | 低                               |
| 用户体验  | 好：预览所见即所得、吸顶预览 + 吸底操作                      | 中：面板遮挡 DLsiteSound 本体      | 差：手编 JSON，非开发者不可用               |
| 风险    | 低：常规 Android 组件                            | 高：SystemUI 内触摸/焦点冲突        | 中：手编易写错范围值导致渲染异常                |
| 上线时间  | 快（可按 §13 分期）                               | 慢                          | 立即（但等于不解决需求）                    |
| 综合评价  | **推荐**                                     | 备选                         | 拒绝                              |

### 5.2 推荐理由

- 与参考项目同构（独立设置 App + 预览 + 显式保存），交互心智已被验证；
- 设置页跑在插件自身进程，不与 SystemUI 抢交互；配置经「标准配置文件」单向流向 SystemUI，边界干净；
- 便于按 MVP 分期交付（§13）。

### 5.3 配置传递选型（实现关键决策）

| 方案     | 说明                                                                                                                                   | 评估                                          |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------- |
| A1（推荐） | 设置页写 SharedPreferences 并将配置文件置为世界可读（world-readable），SystemUI 侧 hook 用 `XSharedPreferences` 读取；保存后 SystemUI 侧 FileObserver 监听变更，热重载样式 | Xposed 生态成熟做法；热重载可让「保存即生效」，减少重启 SystemUI 次数 |
| A2（兜底） | 配置落盘后不热重载，保存成功提示「点击重启系统界面生效」                                                                                                         | 实现最简单，但每次调整都要重启，体验差；作为 A1 失败时的降级            |

**演进路径**：本期按 A1 实现，A2 作为兼容降级开关（配置键 `hot_reload`，默认开）；后续版本再考虑预设主题。

### 6.1 用户画像（基于 Ari 的使用背景，画像为待确认假设）

- **角色**：DLsiteSound 重度用户，同时是本插件作者与测试者（发布到 LSPosed 后有非开发者用户）。

### FR-01 模块激活状态卡

**描述**：设置页顶部状态卡，三态呈现，右侧固定语言切换按钮。

**业务规则**：

1. 已激活态用 MD3 `primaryContainer` 底色 + 勾形图标；未激活态用 `errorContainer` 底色 + 叉形图标；**探测中间态（模块状态未知）用 ? 图标**（与「未激活」的 ✕ 图标区分开，标注 1）。
2. 卡片内容两行：标题（模块已激活 / 模块未激活）+ 副标题 `v{版本名} (code {版本号}) · {SystemUI 授权状态}`。
3. **模块激活判定**：检测 DLsiteSound（`jp.co.eisys.dlsitesound`）是否已在 LSPosed 中授权本模块；已授权即显示「模块已激活」。
4. **SystemUI 授权分立检测**：`com.android.systemui` 的授权状态单独检测，已授权显示「SystemUI 已授权」，未授权显示「SystemUI 未授权」。
5. 数据源：插件自身（版本信息取自本 APK；授权状态经**进程间握手（ConfigBus + ScopeProbe）**间接判定——设置页向 SystemUI 侧 hook 发起握手探测，DLsiteSound 未运行时与「未授权」通过「SystemUI 有响应 → 提示先启动 DLsiteSound」判别化；方案与降级见 §14 风险 RK-02）。
6. **授权检测时机**：进入设置页时检测一次；用户**重新在前台打开设置页时会再检测一次**（非实时监听）。
7. **模块未激活时页面全功能禁用**：检测到「模块未激活」时，页面全功能禁止使用、保存按钮不可用（提示「模块未启用，字幕调整功能无法使用」）。
8. 语言切换按钮：胶囊按钮（🌐 图标 + 当前语言名），点击弹出三选一：简体中文 / 繁體中文 / English。

**验收标准**：

- Given 模块未激活，When 用户打开设置页，Then 状态卡为 `errorContainer` 红底、显示「模块未激活 · v{版本名} (code {版本号}) · SystemUI 未授权」。
- Given SystemUI 已授权但 DLsiteSound 未授权，Then 显示「模块未激活」且副标题中 SystemUI 状态为「已授权」（两状态独立）。
- Given 用户点击语言按钮并选择 English，When 页面刷新，Then 设置页全部文案切为 English，且再次打开记忆上次选择。

### FR-02 设置页语言切换（i18n）

**描述**：设置页支持简体中文 / 繁體中文 / English 三语（标注 1）。

**业务规则**：

1. 切换**设置页 UI** 与**预览区示例字幕**的显示语言（二者同步切换）；
2. 不改变插件在 DLsiteSound 软件内的悬浮字幕显示语言（原代码中已经有显示语言判定标准，不做改动），也不改变 DLsiteSound 本身的语言；
3. 选择持久化到标准配置（`ui_language`，值为 `system` 时跟随系统）。

**验收标准**：

- Given 语言为 English，When 用户在 DLsiteSound 播放字幕，Then 悬浮窗内容不受设置页语言影响。
- Given 语言为 English，When 查看预览区，Then 5 行示例字幕同步显示为英文版本。
- Given 选择「跟随系统」，When 系统语言为繁體中文，Then 设置页显示繁體中文、预览区示例字幕显示繁體版本。

### FR-03 调整预览窗（吸顶）

**描述**：页面顶部固定一块实时预览区（标注 2、7），是所有参数调整的所见即所得画布。

**业务规则**：

1. 预览区三层合成：**用户手机当前壁纸** + **悬浮窗示意（毛玻璃圆角卡片，按真实悬浮窗几何比例渲染）** + **示例字幕**。
2. 示例字幕固定使用以下 5 行（含 1 个活动行，用于同时观察活动行/非活动行效果），并**随设置页语言同步切换**（三语版本见翻译表《可视化调整页面翻译.xlsx》）：
   - 因为想被饲养，也因为想饲养别人（非活动行）
   - 我们互相带上项圈吧（非活动行）
   - **除了我之外**（活动行：加粗、高亮、放大）
   - 绝对不会出现有比我能给你幸福的人（非活动行）
   - 哪里也不要去（非活动行）
3. **实时性**：任何控件拖动/切换过程中预览即时重绘（每帧重绘，不落盘）；
4. **保存动作**：点击「保存设置」后才把当前预览参数写入标准配置，并触发插件悬浮窗本体刷新；
5. **吸顶（标注 7）**：当页面向下滚动、预览区到达顶部时，预览区保持固定在顶部可见；其余设置区从其下方穿过后继续滚动（sticky header 行为）；
6. 预览区使用与编辑无关的独立渲染层（自定义 View），不依赖真实 hook。

**验收标准**：

- Given 用户拖动「阴影半径」滑块，When 停在 15%，Then 预览区字幕阴影立即呈现对应模糊半径，无需保存。
- Given 页面滚动到「字幕排版」区，When 预览区顶边到达屏幕顶栏下沿，Then 预览区固定吸顶、下方内容继续滚动穿过。
- Given 用户调整后未保存直接退出设置页，When 重新进入，Then 预览恢复为**已保存**配置，草稿丢弃（不静默保存，见 §12 异常 E-05）。

**描述**：开关与工具入口（分区标题「其他」，标注 9）。

| 控件          | 类型                  | 默认  | 说明                                                                                                         |
| ----------- | ------------------- | --- | ---------------------------------------------------------------------------------------------------------- |
| 状态栏字幕       | Switch              | 开   | 关闭后**状态栏字幕停止显示，悬浮窗不受影响**（运行时不再 hook/绘制状态栏字幕，无需撤销 LSPosed 授权）；SystemUI 未授权时该开关**置灰禁用**（规则见下方业务规则） |
| 字幕配置备份与恢复   | [⬆ 导出] [⬇ 恢复] 双胶囊按钮 | —   | 导出：将悬浮字幕配置（§10 全量键）序列化为带版本号 JSON 导出到本机文件夹（SAF，用户选目录）；恢复：打开系统文件选择器，允许用户选择此前导出的配置文件恢复到软件中；schema 校验失败拒绝导入并提示 |

**状态栏字幕开关的业务规则**：

1. 「状态栏字幕」开关的可用性由 SystemUI 授权状态决定：检测到 `com.android.systemui` 未授权时，该开关**置灰禁用**（不随用户点击改变），旁附提示「SystemUI 未授权，状态栏字幕不可用」；授权恢复后开关恢复可操作。
2. 授权检测时点：进入设置页时检测一次，且用户**重新在前台打开设置页时会再检测一次**，不实时监听（与 FR-01 判定同源，判定口径见 FR-01 业务规则 5）。
3. 禁用期间**不写入配置**：仅 UI 层置灰，`statusbar_subtitle_enabled` 键值保持不变，避免把「未授权」误记成「用户主动关闭」。

**验收标准**：

- Given 点击「导出」，When 用户选择目录，Then 生成 `dlsitefloat_config_v{n}.json` 并弹出成功提示（含路径）。
- Given 导入一个 `schema_version` 高于当前支持的文件，When 确认恢复，Then 拒绝并提示「配置文件版本过新，请先升级插件」。
- Given 「状态栏字幕」关闭并保存，When 返回 DLsiteSound 播放，Then 状态栏字幕停止显示、悬浮窗正常绘制，设置页其他参数保留。
- Given SystemUI 未授权，When 打开设置页，Then 「状态栏字幕」开关置灰禁用并附「SystemUI 未授权，状态栏字幕不可用」提示，配置键值保持不变。
- Given SystemUI 已授权，When 打开设置页，Then 「状态栏字幕」开关恢复可操作，可正常开/关。

### FR-08 吸底操作栏（重启系统界面 / 保存设置）

**描述**：页面底部固定的双按钮操作栏（标注 6）。

**业务规则**：

1. 操作栏**始终固定在页面底层可见**（不随内容滚动，标注 6「保持保持在页面上层」）；
2. [重启系统界面]：次要按钮（surface 变体灰底）；点击弹二次确认对话框（「将重启 SystemUI，状态栏与通知会短暂消失，确定？」）→ 确认后执行 SystemUI 软重启；用于授权变更、hook 异常等场景；
3. [保存设置]：主要按钮（primary 实心）；点击将全部草稿参数写入标准配置文件（含 `schema_version` 与保存时间戳），成功后：Toast「已保存」+ 触发悬浮窗本体刷新（热重载）或提示需重启（降级，见 §5.3）；
4. 保存采用**全量保存**（不分组保存）；保存后草稿态清零；
5. 存在未保存改动时，返回键/滑动手势退出需弹确认「有未保存的更改」。

**验收标准**：

- Given 未做任何修改，When 查看「保存设置」，Then 按钮仍可点击但保存后提示「配置无变化」。
- Given 点击「重启系统界面」并确认，When SystemUI 重建完成，Then hook 重新加载并按已保存配置渲染字幕。
- Given 有未保存改动按返回，When 弹窗中选择「不保存」，Then 草稿丢弃、配置保持上次保存值。

### FR-09 配置文件 Schema 与读写（技术需求）

1. 配置文件：JSON，含 `schema_version`（整数，本版 = 1）、`saved_at`（ISO 8601）、全量参数键（§10）；
2. 写入采用「临时文件 + 原子替换」防写坏；
3. SystemUI 侧读取失败时**整体回退默认值**并在日志标记，禁止半套参数生效；
4. 键名冻结：新增键只增不改名；废弃键保留解析兼容（读旧配置不丢字段）。

## 九、业务流程与状态流转

### 9.1 编辑-保存状态机（核心）

```
[已保存态] --用户改动任一参数--> [草稿态] --保存设置(成功)--> [已保存态]
    ^                              |
    |                              |--未保存退出(确认放弃)--> [已保存态](回滚预览)
    |                              |--保存设置(失败)--------> [草稿态]（报错，参数保留）
    └------ 恢复默认(仅改草稿) ------ [草稿态]
```

规则：

- 状态 A（草稿）下所有改动**只改预览**；状态 B（保存）才写配置文件；
- 每组「恢复默认」只重置本组，且属于草稿改动（仍需保存）；
- 保存失败（磁盘满/权限异常）必须保留草稿并给出可读错误。

### 9.2 保存生效流程

```
点击保存设置 → 校验范围值(越界夹紧) → 序列化 JSON → 原子写配置文件
  → 成功：通知 SystemUI（FileObserver 触发热重载）→ 悬浮窗刷新
  → 热重载失败/未实现：提示「请点击重启系统界面生效」（A2 降级）
```

### 9.3 恢复配置流程

```
点击恢复 → SAF 选文件 → 解析 + schema 校验（版本/键完整性/范围合法性）
  → 通过：二次确认「将覆盖当前配置」→ 写入 + 预览刷新 + 提示是否重启 SystemUI
  → 失败：明确报错（版本过新 / 文件损坏 / 键缺失），当前配置不变
```

### 16.2 缺陷修复需求

#### BUG-01　宿主存活判别失效（用例 1.2 / 1.4）

- **涉及链路**：`ConfigBus.installResponder`（SystemUI 侧 / 宿主侧应答）、`ScopeProbe`（设置页握手与判定）、状态卡渲染（FR-01 业务规则 3/5、E-10）。
- **修改要点**：
  1. ScopeProbe 收到 `ACTION_HOST_PONG` 时必须校验 `EXTRA_TAG == "host"`；`systemui` 的应答只用于判定 SystemUI 授权，**不得**计入 `hostAuthorized`；
  2. 宿主 PONG 增带实时存活位（`EXTRA_HOST_ALIVE`：存在前台 Activity 或当前正在播放）；SystemUI 侧应答无此位或为 false，视为非宿主；
  3. 状态卡三分支：存活位 true ⇒ 「模块已激活」；宿主进程在但存活位 false ⇒ 「DLsiteSound 未运行」（tertiary 色文案，**页面保持可编辑**，不清空、不禁用保存）；宿主无 PONG ⇒ 按 E-10 引导；
  4. 仅勾选 SystemUI 未勾选宿主时必须落入「DLsiteSound 未运行」态。
- **验收标准**：
  - Given 宿主在前台播放字幕，When 打开设置页，Then 状态卡显示「模块已激活」，副标题 SystemUI 状态独立显示。
  - Given 把 DLsiteSound 从后台划掉（进程可能仍存活），When 打开设置页，Then 显示「DLsiteSound 未运行」（tertiary 色），页面参数可正常编辑与保存。
  - Given 仅勾选 SystemUI 未勾选宿主，When 打开设置页，Then 同上一判据，不显示「模块已激活」。
  - Given 宿主冷启动回到前台，When 重新打开设置页，Then 恢复「模块已激活」（重进前台重检，非实时监听）。

#### BUG-02　配置跨进程持久化失效（用例 2.2 / 2.3，方案 K）

- **涉及链路**：`RemoteConfig`（persistToRemotePrefs / read / applyFromJson）、设置页 `ConfigStore`、SystemUI hook（`StatusBarSubtitleHook`）、宿主 hook。
- **修改要点**：
  1. 废弃「写 remote prefs」路径：不再依赖 `getRemotePreferences` 写入；改为各被注入进程在 `applyFromJson` 收到配置后写入**自身进程本地 SharedPreferences**（MODE_PRIVATE，建议文件名 `dlsitefloat_hook_prefs`）；
  2. 设置页侧保持「自身 MODE_PRIVATE prefs + 广播」，广播继续用于即时生效；
  3. `RemoteConfig.read()` 优先级链固定：**remote prefs（仅读，兼容旧路径）→ 本地 hook prefs → openRemoteFile → 默认值**；允许层级间键缺失回落下一层；
  4. 进程冷启动自恢复：SystemUI / 宿主 hook 初始化即按上述链路读取，不依赖设置页广播。
- **验收标准**：
  - Given 修改「主字幕颜色」并保存成功，When **重启手机**（全程不打开设置页）后播放字幕，Then 悬浮窗颜色与保存值一致。
  - Given 重启后未打开设置页，When 观察状态栏字幕与悬浮窗，Then 全部参数为上次保存值，不回默认。
  - Given 上述流程，When 查看 logcat，Then 不再出现 `persistToRemotePrefs failed` 与 `Read only implementation`。

#### BUG-03　保存未即时生效（用例 2.1）

- **涉及链路**：hook 侧 `CONFIG_CHANGED` 接收 → `refreshStyle` → 悬浮窗 View / 状态栏字幕 View；设置页 FR-08 保存流程。
- **修改要点**：
  1. 收到 CONFIG_CHANGED 后除更新样式对象外，必须对已 attach 的悬浮窗 Root / 字幕 View 调 `invalidate()` 强制重绘；
  2. 状态栏字幕对**当前正在显示的行**用新 paint 立即重画（重新 showLine 当前文本，或对该行 View 重设 paint 后 invalidate），不得等待下一次换行；
  3. 悬浮窗未开启时不触发 hook（空指针防护），已开启则无条件重绘。
- **验收标准**：
  - Given 悬浮窗开启且字幕正在播放、当前行未换行，When 修改主字幕颜色并保存，Then 1 秒内悬浮窗当前行与状态栏当前行同步变色。
  - Given 音轨未播放但悬浮窗仍开启，When 修改并保存任意参数，Then 悬浮窗可见部分立即呈现新样式（无需重启、无需重新打开悬浮窗）。

#### BUG-04　显示大小 / 字体大小导致排版崩坏（用例 3.11）

- **涉及链路**：设置页 Activity（`attachBaseContext` / `onConfigurationChanged`）、AndroidManifest 中该 Activity 的 `configChanges`。
- **修改要点**：
  1. `attachBaseContext` 在现有 fontScale=1.0 基础上，尝试读 `Settings.Secure` 的 `display_density_forced`，**读到才钉** `densityDpi`，读不到不做无依据猜测；
  2. Manifest 为设置 Activity 增加 `configChanges`（fontScale / density / smallestScreenSize / screenSize / layoutDirection / uiMode / orientation 等），并在 `onConfigurationChanged` 中按同一套逻辑重钉；
  3. 明确兜底：读不到 forced density 时允许页面等比缩放，但必须保证不出现「疯狂换行」级崩坏（卡片内单行文本允许 ellipsize / 受控折行，按 NFR-04 处理）。
- **验收标准**：
  - Given 系统「字体大小」拉到最大，When 打开设置页，Then 排版与字体大小=默认时一致。
  - Given 系统「显示大小」拉到最大，When 打开设置页，Then 无控件重叠、无多处非预期换行，所有控件与按钮可点可滑。
  - Given 设置页在前台，When 修改系统显示大小后切回设置页，Then `onConfigurationChanged` 重钉生效，排版仍不崩。

#### BUG-05　仅切换语言误判脏数据（用例 6.3）

- **涉及链路**：`SubtitleConfig.sameParametersAs`（脏判定）、`ConfigStore`（新增 `saveUiLanguageOnly`）、FR-02 语言切换、FR-08 未保存退出确认。
- **修改要点**：
  1. `sameParametersAs` 的比较项剔除 `uiLanguage`；
  2. 语言点击后立即调用 `saveUiLanguageOnly`：只写设置页 MODE_PRIVATE prefs 的 `ui_language` 键，**不写 JSON、不发广播、不覆盖其他参数、不进草稿态**；
  3. 语言保存失败（极端 IO 异常）时 Toast 提示，不影响页内其他编辑与保存。
- **验收标准**：
  - Given 进入设置页后**只**点击语言按钮切换语言，When 按返回，Then 不弹「有未保存的更改」。
  - Given 未做任何参数改动、切换语言后杀掉设置页进程重进，When 查看语言，Then 为上次所选语言。
  - Given 已有未保存的参数草稿，When 切换语言，Then 草稿仍保留，按返回仍提示未保存；切语言本身不产生脏位。

#### BUG-06　无字幕轨时旧字幕残留（用例 7.2）

- **涉及链路**：hook 侧字幕接收与挂起判定（`heldSoftVerdict` / cues 缓存）、悬浮窗绘制、状态栏字幕绘制。
- **修改要点**：
  1. 收到「无字幕轨 / 字幕轨结束」信号时，立即清除 `heldSoftVerdict` 持有的 cues 缓存与已显示行；
  2. 清除后收起或清空悬浮窗与状态栏的字幕内容，**不得**因等待下一行动作而永久保留最后一行；
  3. 恢复播放并重新有字幕轨时，按正常流程重新显示，不得误清。
- **验收标准**：
  - Given 播放带字幕的作品后切到无字幕轨的音轨（或字幕轨结束），When 观察悬浮窗 / 状态栏，Then 旧字幕内容消失，不留存最后一行。
  - Given 之后再次触发有字幕内容，When 观察，Then 字幕正常重新出现，无残留叠加。

#### UI-09　新增「悬浮窗颜色」（3.1.5）

- 位置：「字幕排版」组内，**「长字幕内换行额外行距」下方**。
- 色板：8 预设 —— 深蓝黑 / 白 / 绿 / 红 / 橙 / 青 / 紫 / 深蓝，行末 🎨 自定义（同 UI-06 圆形按钮规格）。
- **色板圆点渲染**：显示**面板顶部实际不透明度叠加后的效果**（半透明感），**不显示实心色**，并体现面板圆角形态与实际悬浮窗一致。
- 默认值：深蓝黑 `#0E1420`；面板不透明度沿用现有方案：顶部 `0x4D × 1.9 ≈ 146/255 ≈ 57%`、底部 `0x30 × 1.9 ≈ 91/255 ≈ 36%`，渲染为**从上到下渐变**：顶部 `0x920E1420` → 底部 `0x5B10172A`，圆角 **20dp**（渲染逻辑属 hook 侧悬浮窗职责，设置页预览窗必须同步同一逻辑）。
- 自定义取色只取 RGB，Alpha 强制 `0xFF` 作为「基色」，叠加效果由渲染端换算。
- 「恢复默认」小字补充「悬浮窗颜色 黑色」并三语（见 16.6）。
- **验收标准**：
  - Given 首次安装或使用恢复默认，When 查看该行缺省色，Then 为深蓝黑且呈半透明渐变感，非实心色块。
  - Given 选择任意预设色并保存，When 观看真机悬浮窗，Then 面板颜色与预览 / 色板观感一致（同一不透明度叠加策略、同样 20dp 圆角）。
  - Given 使用 🎨 自定义，When 取色并应用，Then 存储值为 `0xFF` + 所选 RGB，渲染时按默认不透明度策略叠加。

#### UI-10　导入失败提示细分（5.1.1）

| 场景 | 触发判定 | 提示（三语见 16.6） |
| ---- | ---- | ---- |
| 非 JSON 文件 | 选中文件无法按 JSON 解析 | 导入失败：非字幕配置文件 |
| 空文件 | 文件长度为 0 或解析结果无任何键 | 导入失败：字幕配置文件为空 |
| 内容不合规 | 可解析但 schema 校验失败（键缺失 / 越界 / 版本不支持） | 导入失败：非字幕配置文件或文件内容损坏 |

- 三种失败均**不改动当前配置**；FR-07 既有「版本过新」提示保留独立优先级，不并入上表。
- **验收标准**：分别构造上述三类文件执行导入，Then 提示文案与上表逐字对应；导入失败后当前配置保持原值。

| `float_window_color` | int（ARGB） | RGB 任意；经 🎨 自定义时 Alpha 固定 `0xFF`（基色），面板实际透明度由渲染端按策略叠加换算 | `#FF0E1420`（深蓝黑） | 悬浮窗颜色（UI-09） |

### 17.2 缺陷修复需求

#### BUG-R01　作用域判定与宿主判活失效（用例 2.1.1 / 2.6 / 2.8）

- **涉及链路**：`DlsiteSoundSubtitleModule.onPackageLoaded`、`ConfigBus.installResponder` / `isHostAlive`、`SettingsActivity` 状态卡渲染。
- **修改要点**：
  1. `onPackageLoaded` **只对目标包**（`jp.co.eisys.dlsitesound`）挂钩子；非目标包（含 SystemUI）不得挂 `Application#attach`。此前未过滤，导致 SystemUI 进程也执行了 `installResponder(ctx, "host")`。
  2. `ConfigBus.installResponder` 增加**进程名硬闸**：`tag == "host"` 时必须确认当前进程是宿主进程，否则拒绝安装并记录告警。
  3. `isHostAlive()` 改为读**进程调度优先级**（`ActivityManager.getMyMemoryState` 的 `importance`），不再使用「播放页可见 ∪ 正在播放」这一族会随暂停抖动、且把「未知」当「在播」的信号。
- **验收标准**：
  - Given 宿主在前台播放中，When 打开设置页，Then 显示「模块已激活」。
  - Given 暂停播放（宿主进程仍在），When 打开设置页，Then **仍显示**「模块已激活」（暂停不算未运行）。
  - Given 把宿主从后台划掉，When 打开设置页，Then 显示「DLsiteSound 未运行」（tertiary 色），页面**保持可编辑**。
  - Given 只勾 SystemUI、未勾宿主，When 打开设置页，Then 显示「模块未激活」（error 色）+ 去 LSPosed 勾选与重启的引导。
  - Given 只勾宿主、未勾 SystemUI，When 打开设置页，Then 显示「模块已激活」+ 副标题 `SystemUI 未授权` + 引导小字。

#### BUG-R02　远端配置写入失败日志刷屏（用例 10.5）

- **修改要点**：`RemoteConfig.applyFromJson` **不再尝试写入远端配置**（LSPosed 2.2.0 在被注入进程是只读实现），只保留本进程本地 `MODE_PRIVATE` 写入；`persistToRemotePrefs` 方法整体删除。
- **验收标准**：抓 logcat 搜相关关键字，**不再出现**该失败日志与`只读实现`异常。

#### UI-R01　分区顺序与真吸顶（用例 1.1 / 1.7）

- **要点**：`CoordinatorLayout` 根布局内，`AppBarLayout` 子 View 顺序 = 页头行 → **状态卡** → 状态引导 → 「调整预览窗」标题 → 预览卡 →（NestedScrollView：四组卡片）→ 吸底栏。前两项 `scroll|enterAlways`、后两项 `noScroll`。

### 18.2 真 bug 根修

#### BUG-S01　设置页四组小按钮：样式资源被当成「样式属性」传（用例 1.2 / 1.1.3）

- **现象**：重置 / 对齐 / 导出 / 导入 渲染成「深色底 + 黑字」（读不清）；分段按钮三段同色（Ari 判成「对齐点选不可用」）；整页处于禁用态时导出 / 导入**整块消失**（录屏证据）。
- **根因**：v1.5 用 `new MaterialButton(ctx, null, R.style.Widget_Material3_Button_TonalButton)`。
  `MaterialButton` 的三参构造第三个参数是 **`defStyleAttr`（属性 id）**，不是 style 资源 —— 传 style 资源进去解析不到，
  tonal 的 `backgroundTint = colorSecondaryContainer` 与 `android:textColor = colorOnSecondaryContainer` **两条都没落地**，
  于是背景退回默认的 `colorPrimary`（浅色模式下 = 深青）而文字仍是 `?android:textColorPrimary`（黑），
  出现「深底压黑字」；分段按钮三段全走同一条回落 ⇒ 选中与未选中完全同色。
  禁用态时因为 `backgroundTint` / `textColor` 都是空 ColorStateList，控件直接渲染成透明 ⇒ 「一片空白」。
- **修法**：不再传 style 资源。改为造普通 `MaterialButton` 后**显式**写三条：
  `setBackgroundTintList(colorSecondaryContainer)`、`setTextColor(colorOnSecondaryContainer)`、
  `setIconTint(colorOnSecondaryContainer)`；并统一用一个带**禁用态（同色 38% 不透明度）**的 `ColorStateList` 工厂
  （`SettingsActivity#colorStateList`），彻底消除「禁用即消失」。
- **对齐分段按钮**：不再依赖 `MaterialButtonToggleGroup` 的内部 checked 态色；段与段之间的选中态由
  `SettingsActivity#paintSegments` 直接画 —— 未选中 = 透明底 + `colorPrimary` 文字，选中 = `colorSecondaryContainer` 底 +
  `colorOnSecondaryContainer` 文字；外层是一圈 1dp `colorOutline` 描边的 20dp 圆角「轨道」。
- **验收**：浅色 / 夜间两种模式下，四组按钮文字与底色对比充分；对齐三段点谁都立刻能看出选中；整页禁用时按钮呈半透明灰而非消失。

#### BUG-S02　悬浮窗彩色面板下 ✕ / 缩放手柄不转白（用例 6.1.1，Ari 第二次点名）

- **现象**：面板为绿色等彩色时，✕ 与右下缩放手柄仍为中灰。
- **根因**：**判据是对的，调用时机是错的**。`FloatingSubtitleView.init()` 先调 `applyPanelBackground()`
  （它内部顺手调 `applyControlTint()`），而那一刻 `closeBtn` / `gripView` **还没 new 出来** ⇒ 两个 `if (xx != null)` 全部落空，
  控件保持构造函数里写死的中灰；之后唯一的补色入口是 `refreshStyle()` 里「面板色变了才重建背景」那条分支，
  而**视图重建时 `style` 是新建的**（`old == null` 直接 return）⇒ 只要一开就是彩色面板，这条补色链永远走不到。
- **修法**：在 `init()` 末尾（控件全部 `addView` 完）**补调一次** `applyControlTint()`。
- **验收**：面板选绿 / 红 / 橙 / 青 / 紫 / 蓝（以及深蓝黑以外的任意自定义色）时，✕ 与手柄呈**白色 40%**；选黑 / 白 / 深蓝黑时维持中灰 40%。

### 18.4 关于「炫光能不能做悬浮窗背景」（Ari 2.2 的提问）

**能，但不是「把某个颜色换成炫光」那么简单，需要分两种情况说清楚**（本轮未实装，仅回答）：

1. **真正的「背景模糊 / 液态玻璃」（壁纸透过面板）**：需要 `WindowManager.LayoutParams.setBlurBehindRadius()` +
   `FLAG_BLUR_BEHIND`，且在 Android 12+ 上受 ROM 白名单限制。本项目现有代码里 `ENABLE_SYSTEM_BLUR_BEHIND` 在
   ColorOS 上是**关掉**的 —— 真机实测系统模糊会把整屏糊掉（见 `FloatingSubtitleView.applyPanelBackground` 的注释），
   所以这条在 Ari 的机器上不可用。
2. **「炫光」本身（面板自带的多色渐变 / 光晕）**：这个是**纯绘制**，完全可实现、无权限门槛。
   做法是把 `GlassPanelDrawable` 的「两档纯色垂直渐变」换成**多色 `SweepGradient` / 多停靠点 `LinearGradient`**，
   停靠点颜色由配置基色在 HSV 上做 ±20° 色相偏移 + 明度微调生成（这样任何一个基色都能推出属于它的「炫光」，
   而不是只有一套固定彩虹）。成本只有一个：`SubtitleStyle` 要新增一组「停靠点色」字段，
   并保证 `sameAs()` 把它算进比较（否则改色不重绘）。
3. **本轮的处理**：Ari 说「之后考虑」，所以 2.3.2 **没有**改面板绘制，只把**预览窗**做成三层叠加的真实观感。
   若要做，建议单开一个版本，并同时给出「炫光强度 0–100%」的回退开关。

**用户可见的功能逻辑零改动。** 本轮只做三件事：

### 19.3 根因

`res/drawable/ic_import.xml` 的 `android:pathData` 写成了：

```
M19,9h-4L15,3L9,3v6L5l7,7 7,-7zM5,18v2h14v-2L5,20z
                          ↑ 位置 19
```

**两处错，一个会崩、一个会画歪：**

| # | 位置 | 写法 | 问题 | 后果 |
| ---- | ---- | ---- | ---- | ---- |
| 1 | `…v6` **`L5`** `l7,7…` | `L5` | `L` 是「绝对折线到」，**必须跟成组的 x,y（偶数个）**，这里只给了 1 个坐标（原作者是把官方的 `H5` 手工改写成 `L5` 时漏了 y） | 🔴 **真机直接抛异常**，设置页起不来 |
| 2 | `…v-2` **`L5,20`** `z` | `L5,20` | 语法合法（2 个坐标），但几何含义是「从 (19,18) 斜拉到 (5,20)」，而原本应是「水平拉到 (5,18)」 | ⚠️ 托盘右下角画成一条**斜线** |

**为什么编译期发现不了：**

- `pathData` 在 `resources.arsc` 里就是一段**普通字符串属性**，`aapt2` **不做语法校验**；
- 因此 `assembleDebug` 一路绿灯，`aapt2 dump badging` / `dump xmltree` 也都能正常打出这条属性；
- 只有**真机 `VectorDrawable` 解析**（`PathParser.nCreatePathDataFromString`）时才会抛 `IllegalArgumentException`；
- 而它是在 `onCreate → buildRows → buildMiscGroup → makeTonalButton → setIconResource` 这条**建行链**上被触发的 ⇒ **Activity 还没显示就崩了**，用户看到的就是「点一下、黑一下、退回桌面」。

> 因此这个问题**不会被**「看一眼页面」「跑一下单元测试」「比对 dex」中的任何一种手段发现 —— 它只活在「资源编译产物」与「真机解析器」之间的缝隙里。

### 19.4 修法

两个图标**双双改用 MD 官方原始路径数据**，不再做「把横/竖线段改写成折线命令」这类等价改写（那正是漏坐标的高发动作）：

| 文件 | 修复后 pathData |
| ---- | ---- |
| `res/drawable/ic_import.xml`（file_download） | `M19,9h-4V3H9v6H5l7,7 7,-7zM5,18v2h14v-2H5z` |
| `res/drawable/ic_export.xml`（file_upload） | `M9,16h6v-6h4l-7,-7 -7,7h4v6zM5,18h14v2H5z` |

`ic_export` 原写法（`…h14v2L5,20v-2z`）其实**语法合法、几何也正确**，一并统一只是为了两个文件写法一致、避免后来者照抄时再漏坐标。两个文件的注释里都写明了这条教训。

### 19.5 新增验证层：矢量路径离线校验

**问题出在哪：** 既有验证链是两层 ——

| 层 | 覆盖 | 能否发现本问题 |
| ---- | ---- | ---- |
| dex 三层（§3 常量池 / 方法签名 / 指令序列） | Java/Kotlin 代码 | ❌ 该问题不在 dex 里 |
| 资源层（§3.7 二进制 XML / Manifest） | 布局属性、清单 | ❌ 只看元素与属性名，不看属性**值的语义** |

⇒ **矢量图标路径的取值合法性，两层都不管。** 本轮补上第三层：

**`_rel232/verify_pathdata.py`（源码层，可独立运行）**

1. **命令元数自洽**：按 SVG 路径语法逐段校验命令后跟的坐标个数
   （`M/L/T` 需 2 的倍数、`C` 需 6 的倍数、`S/Q` 需 4 的倍数、`A` 需 7 的倍数、`H/V` 需 1 的倍数、`Z` 后不得跟数字）；
2. **子路径包围盒不越界**：对只含 `M/L/H/V/Z` 的路径精确计算每条子路径的包围盒，检查是否落在 `viewport(0,0,24,24)` 内；
3. 扫描范围 = `app/src/main/res/drawable*/` 下**所有** `<vector>`。

**`_rel233/verify_233.py`（出包层）**

把判据**打在最终 APK 上**而不只是源码上：从 `apk_233.apk` 里 dump 出每个矢量资源的 `pathData` 再喂给同一套校验器 —— 证明「**打进包的那一份**」是对的（源码对 ≠ 包里的对）。

**`selftest_pathdata.py`（校验器自测）** —— 13 条构造样例，确认校验器有区分力：

| 样例 | 期望 | 实测 |
| ---- | ---- | ---- |
| 真实坏例（`L5` 只跟 1 个坐标） | FAIL | FAIL ✅ |
| 修复后的两个图标 | OK | OK ✅ |
| 坐标越界（飞到 30） | WARN | WARN ✅ |
| `M` 后奇数个坐标 / `C` 只给 3 个 / 首条非 `M` / `Z` 后跟数字 / 命令后无坐标 | FAIL | 全 FAIL ✅ |
| `H5,5`（H 允许多组，合法） | OK | OK ✅ |
| 含弧线的圆角矩形（几何层跳过） | OK | OK ✅ |

> ⚠️ **该层的已知边界（必须写清楚）**：它能抓「元数错（会崩）」与「坐标越界」，
> **抓不到「形状错但坐标全部合法」**（如 `L5,20` 那条斜线）—— 后者仍需人眼或渲染验证。
