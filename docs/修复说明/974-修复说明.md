## 2. 五条返工逐条说明

### 2.1 滑块 → M3 Expressive 形态（粗轨道 + 竖长手柄）

**先做的可行性论证**（决定了实现路径，不是拍脑袋）：

反汇编 Material 1.9.0 的 `BaseSlider` / `Slider`，得到两条硬约束：

1. **`thumbWidth`/`thumbHeight` 属性在此版本不存在** —— 只有圆形 `thumbRadius`。
2. `BaseSlider#adjustCustomThumbDrawableBounds` 的缩放公式是
   `scale = 2×thumbRadius / max(固有宽, 固有高)`，两个 bounds 都按它算
   ⇒ **落地高度恒 = 2×thumbRadius**；自定义 Drawable 的固有尺寸**只表达宽高比**，
   不表达绝对大小。⇒ 想得到 4×44dp 的竖长手柄，必须 `setThumbRadius(22dp)`。
3. **顺序不可反**：比例在 `setCustomThumbDrawable` 那一刻算 ⇒ 必须**先** `setThumbRadius`、
   **后** `setCustomThumbDrawable`。

落地参数：

| 部件 | 值 | 颜色 |
|---|---|---|
| 轨道高 | 16dp | 左侧 `colorPrimary` / 右侧 `colorSecondaryContainer` |
| 手柄 | 4dp × 44dp（thumbRadius 22dp） | `colorPrimary`（圆角胶囊，cornerRadius 2dp） |

代码（`SettingsActivity.java`）：

```java
private static final int SLIDER_TRACK_H_DP = 16;
private static final int SLIDER_THUMB_W_DP = 4;
private static final int SLIDER_THUMB_H_DP = 44;

private void applyExpressiveSlider(Slider slider) {
    int active   = attr(com.google.android.material.R.attr.colorPrimary,             0xFF6750A4);
    int inactive = attr(com.google.android.material.R.attr.colorSecondaryContainer,  0xFFE8DEF8);
    slider.setTrackHeight(dp(SLIDER_TRACK_H_DP));
    slider.setTrackActiveTintList(android.content.res.ColorStateList.valueOf(active));
    slider.setTrackInactiveTintList(android.content.res.ColorStateList.valueOf(inactive));
    slider.setThumbRadius(dp(SLIDER_THUMB_H_DP / 2f));          // ← 必须先于下一行
    slider.setCustomThumbDrawable(makeExpressiveThumbDrawable(active));
}

private Drawable makeExpressiveThumbDrawable(int color) {
    GradientDrawable bar = new GradientDrawable();
    bar.setShape(GradientDrawable.RECTANGLE);
    bar.setColor(color);
    bar.setCornerRadius(dp(SLIDER_THUMB_W_DP / 2f));
    bar.setSize(dp(SLIDER_THUMB_W_DP), dp(SLIDER_THUMB_H_DP));   // 只表达 4:44 比例
    return bar;
}
```

`addSliderRow` 在 `setLabelFormatter` 之后插一行 `applyExpressiveSlider(slider);`。
拖拽行为由 `Slider` 原生提供，**未改**逻辑 ⇒ 「可拖动改变数值」不变。

### 2.4 卡片最下方文字底距 → 6dp（量的是「字形底」）

**难点**：TextView 的 `getHeight()` 底边≠字形底 —— 字体自带 descender 与 `includeFontPadding`
会在字形底下留一条看不见的空白。直接写 `paddingBottom(6dp)` 得到的**视觉底距会大于 6dp**。

**做法**（两段）：

1. `setIncludeFontPadding(false)` 消掉字体自带的额外 padding；
2. 布局完成后（`addOnGlobalLayoutListener`，用完即摘），量出**末行墨迹底**，
   用**负 bottomMargin** 把多出来的空白抵消掉：

```java
private void pinCardLastTextInk(final LinearLayout group, final TextView text) {
    // …摘监听、取 LinearLayout.LayoutParams…
    android.text.Layout layout = text.getLayout();
    int line  = layout.getLineCount() - 1;
    int start = Math.min(layout.getLineStart(line), cs.length());
    int end   = Math.min(layout.getLineEnd(line),   cs.length());
    Rect ink = new Rect();
    text.getPaint().getTextBounds(cs, start, end, ink);          // 末行墨迹矩形
    int baseline  = layout.getLineBottom(line) - layout.getLineDescent(line);
    int inkBottom = text.getPaddingTop() + baseline + ink.bottom; // 墨迹底（相对 View 顶）
    int slack     = text.getHeight() - inkBottom;                 // 墨迹底以下的多余空白
    int want = -Math.min(Math.max(slack, 0), dp(CARD_PAD_BOTTOM_DP));
    llp.bottomMargin = want;                                      // 负 margin 计入总高 ⇒ 等效下沉
}
```

**为什么用负 margin**：线性布局里负 `bottomMargin` 会计入总高 ⇒ 等效「把文字往下沉 slack」，
于是 `视觉底距 = paddingBottom(6dp) + (−slack) + slack = 6dp` 成为**恒等式**。
`Math.min(slack, 6dp)` 是上界闸门：若 slack 本身小于 6dp，就只抵消 slack，不会把文字压出卡片。

挂在 `addResetRow` 末尾（`pinCardLastTextInk(parent, hint);`）—— 四张卡的最末行都走这条路径。
