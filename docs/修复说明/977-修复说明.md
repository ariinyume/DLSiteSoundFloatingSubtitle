## 2. 根因（三条，缺一不可）

### ① 轮询会永久停机，且没有重启入口
旧代码：连续 `POLL_IDLE_STOP_MS(15s)` 无真实样本 ⇒ `sPollScheduled=false` **永久停机**；
而**唯一的重启入口 `ensurePolling()` 只在模块随进程加载时调一次**。
⇒ 一旦停就再也不会恢复，恰好错过用户切轨的那一刻。

### ② 「距上次太久就重种基线」把比较分支彻底堵死
`PlayerSourceHook` 里：
```java
if (last == null || since > INDEX_STALE_MS /*30000*/) { /* 只种基线，不比较 */ }
```
在读数本来就 40~140 秒一次的现实下，这条**几乎每次都命中**
⇒ 相邻两次读数**永远走不到「比较」那一步** ⇒ 换轨 0 次上报。

> ⚠️ **976 的离线模拟没能暴露它**：模型假设读数间隔 **500ms**，与真机差两个数量级。
> 这是本轮最重要的方法学教训 —— 时序模型不只要求「带自检」，**采样节奏也必须是真机实测的**。

### ③ `AudioPlaylist` 实例被 `AudioPlayer` 挤出保留表
只有 `AudioPlaylist` 的状态 Map 才带 `currentIndex`（`AudioPlayer` 的不带）；
旧的 `rememberPlayer` 在满表时无脑 `remove(0)`，宿主高频调 `AudioPlayer` 时会把
`AudioPlaylist` 挤出去 ⇒ 轮询**再也读不到序号**。

## 3. 修法（三处代码 + 一处只读诊断；**去抖判据一字未动**）

| 位置 | 改动 | 目的 |
|---|---|---|
| `PlayerPositionHook` | 空闲只**降频**（1s → 3s），只有 `POLL_HARD_STOP_MS(600s)` 完全无样本才真停；每 10s 打一条 `poll tick #N players=… idle=…ms` | 根治 ①，并留下「轮询还活着」的自证 |
| `PlayerPositionHook` | 淘汰实例时优先「**同类里最旧的**」，上限 4 → 6 | 根治 ③ |
| `PlayerSourceHook` | `if (last == null \|\| since > INDEX_STALE_MS)` → **`if (last == null)`** | 根治 ② |
| `PlayerPositionHook` | 新增 `dumpStatusMap`：按来源分档节流（2.5s）的**状态 Map 全量转储** | **只读**诊断；若仍失败，一眼看出「哪个通道带 currentIndex」 |

**新增常量**：`POLL_IDLE_SLOW_MS=15000`、`POLL_SLOW_INTERVAL_MS=3000`、`POLL_HARD_STOP_MS=600000`、
`POLL_LOG_EVERY_MS=10000`、`MAX_REMEMBERED_PLAYERS=6`、`MAP_DUMP_MIN_INTERVAL_MS=2500`。
**删除常量**：`POLL_IDLE_STOP_MS`（正是它导致永久停机）。

### 为什么这不会像 975 那样「修错方向」
975 的错在于「改判据去适应一个臆测的时序」。本轮**没碰判据**，改的是**采样的可靠性**——
三条改动都能在日志里直接验证（`poll tick` / `statusMap via=` / `>>> track changed`），
不依赖任何对宿主行为的猜测。

## 7. 怎么验（真机）

1. 装 `DLsiteFloat-2.2.5-code977-debug.apk`（版本号确认 `2.2.5` / code `977`）。
2. 播放一个**有字幕**的作品 → 切到**没有字幕**的作品/音轨。
3. **期望**：悬浮窗在约 5 秒内关闭（或先显示「无字幕」再关），状态栏字幕停止显示旧内容。
4. 若复现失败，请抓日志 —— 只要看到这三行就能定位：
   - `[DLsiteSoundFloat:Pos] poll tick #N players=K idle=…ms` ← 轮询活着吗
   - `[DLsiteSoundFloat:Pos] statusMap via=… {currentIndex=…, duration=…}` ← 哪个通道带序号
   - `[DLsiteSoundFloat:Source] >>> track changed: … 0->N` ← 换轨有没有上报
