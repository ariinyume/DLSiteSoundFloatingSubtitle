## 一、设计图：整体骨架

### 1.1 页面结构（两层吸顶 + 一层吸底）

```
┌─ settings_root（垂直 LinearLayout，页面大底色）──────────────────┐
│ ┌─ settings_coord（CoordinatorLayout，weight=1）───────────────┐ │
│ │ ┌─ settings_appbar（AppBarLayout，paddingBottom=5dp）──────┐ │ │
│ │ │ ① 页头行     DLsiteFloat + 副标题 · [🌐 简中]   ← scroll  │ │ │
│ │ │ ② 状态卡     激活态 + 版本号 + SystemUI 状态    ← scroll  │ │ │
│ │ │ ②' 引导小字   未激活/未授权时的引导            ← scroll  │ │ │
│ │ │ ──────── 第一个 noScroll 从这里开始 ────────            │ │ │
│ │ │ 「调整预览窗」节标题                        ← noScroll   │ │ │
│ │ │ ③ 预览卡（三层叠加）                        ← noScroll   │ │ │
│ │ └────────────────────────────────────────────┘ │ │ │
│ │ ┌─ settings_scroll（NestedScrollView）──────┐   │ │ │
│ │ │ ④ 主字幕 / 活动行调整  → card_main        │   │ │ │
│ │ │ ⑤ 非活动行字幕调整    → card_inactive     │   │ │ │
│ │ │ ⑥ 字幕排版            → card_typo         │   │ │ │
│ │ │ ⑦ 其他                → card_misc         │   │ │ │
│ │ └───────────────────────────────────────────┘   │ │ │
│ └──────────────────────────────────────────────────┘ │ │
│ ┌─ bottom_bar（真实占位的兄弟节点）────────────────────┐  │
│ │  [重启系统界面]（tonal）  [保存设置]（primary）      │  │
│ └────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────┘
```

### 1.2 三个结构性决策（都是踩坑换来的，别改回去）

| 决策                                             | 为什么                                                                                                                                                                                |
| ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **根布局是垂直 LinearLayout，底栏是它的兄弟节点**              | 2.1.4 之前底栏是 CoordinatorLayout 的 `layout_gravity="bottom"` 直接子 View，不占滚动区高度，靠「实测底栏高 → 写进内容 paddingBottom」让位。ARI 截图实证后果是**最后一行压在栏下、滚不出来**（"拉不到底"）。改成真实占位后，滚动区高度 = 剩余空间，不再依赖任何时序/高度测量 |
| **页头行/状态卡用 `scroll`，不用 `scroll\|enterAlways`** | `enterAlways` 语义是「往上滚一点立刻回来」，ARI 要求「页头不要跟预览一起吸顶出现」。改 `scroll` 后只在滚回最顶部时出现，顺带消掉了与 NestedScrollView 抢滚动量的顿挫                                                                          |
| **预览区不能改成 `exitUntilCollapsed`**               | AppBarLayout 求可滚动高度时会把该子 View 的 `minHeight` 减掉；wrap_content 卡片没设 minHeight ⇒ 吸顶量 0，整张卡跟着滚走。已反编译 material 1.9.0 的 `getTotalScrollRange` 确认                                          |

## 二、逐模块设计逻辑

### ① 页头行（AppBarLayout 内，`scroll`）

- 左：大标题 `DLsiteFloat`（26sp bold）+ 副标题「DLsiteSound 悬浮窗 · 状态栏字幕外观调整」
- 右：**语言胶囊**（`language_button`）
  - 高 32dp ⇒ 全圆角 16dp；背景 `?attr/colorPrimary`，文字/图标 `?attr/colorOnPrimary`
  - **LinearLayout 自绘**（ImageView + TextView），不是 MaterialButton + `app:icon`  
    → v1.5 真机上 MaterialButton 只画出图标、文字被 icon 布局吃掉；拆成两个兄弟 View 后不可能再互相吞
  - 可见文字 = **当前语言的短名**（简中 / 繁中 / EN）；完整语义走 `contentDescription` 无障碍朗读
  - 点开弹单选：跟随系统 / 简体中文 / 繁體中文 / English

### ② 状态卡（四态渲染，探测驱动）

| 态         | 判据                             | 底色（MD3 色槽）               | 图标         | 引导小字                    |
| --------- | ------------------------------ | ------------------------ | ---------- | ----------------------- |
| 探测中       | `mProbe == null`               | `colorSurfaceVariant`    | unknown    | 隐藏                      |
| **已激活**   | `hostAuthorized && hostAlive`  | `colorPrimaryContainer`  | status_on  | 隐藏                      |
| **宿主未运行** | `hostAuthorized && !hostAlive` | `colorTertiaryContainer` | unknown    | 「请启动 DLsiteSound」       |
| **未激活**   | `!hostAuthorized`              | `colorErrorContainer`    | status_off | 「去 LSPosed 勾作用域」/ 未知态文案 |

设计逻辑上的三个关键点：

1. **`hostAlive` 与 `hostAuthorized` 是两件事**。ARI 把 DLsiteSound 从后台划掉后宿主进程往往还活着，`installResponder` 照样答 PONG、授权位仍是 true ⇒ 只看授权位会把「划掉了」显示成「已激活」（用例 1.2）。`hostAlive` 由宿主在 PONG 里带上来（`ConfigBus.EXTRA_HOST_ALIVE`），**缺省 true**（老版本模块不带这个 extra，必须保持已激活，不能误降级）。
2. **「能不能编辑」只看授权位，不看存活位**。宿主未运行 ⇒ 页面保持可编辑、保存可用、**不清空任何参数**（配置照改照存，宿主起来后由 hook 侧补推广播生效）。只有真·未授权才整体禁用（STA-07）。
3. **副标题固定输出**：`版本名 + versionCode + SystemUI 状态`，例：`2.2.1 (973) · SystemUI 已授权`。

### ③ 预览卡（真窗同构，钉在顶部）

三层叠加，全部取自**同一份草稿配置**：

```
preview_backdrop  ← 壁纸近似底（TL_BR 四色渐变，🔴 必须完全不透明）
   ↓ preview_panel ← 悬浮窗面板：基色 RGB × 上 0x92 / 下 0x5B 垂直渐变，20dp 圆角
      ↓ preview_lines ← 5 行示例字幕，每行一个独立 TextView
```

- **三层而不是一层的原因**：v1.5 用的是半透明壁纸层（alpha 0.85/0.70/0.55），整张预览卡是半透明的 ⇒ 吸顶时底下滚动过去的「模糊半径」等行会**透出来**（ARI 截图里预览卡中出现了滑块的怪象），左右边缘也显出被覆盖内容的地色。做成不透明后预览块才是一块真正的实体面板。
- **容器必须是普通 FrameLayout**：MaterialCardView 会用自身 MaterialShapeDrawable 顶掉 `setBackground()` ⇒ v1.5 那层半透明面板**一次都没画出来过**。圆角靠背景 GradientDrawable 的 20dp 提供轮廓，配 `clipToOutline="true"`。
- **5 行示例字幕随界面语言切换**（简中 / 繁中 / EN 三套），**第 3 行「除了我之外」是活动行**（`PREVIEW_ACTIVE_INDEX = 2`，PRD 显式指定）。文案必须在每次重绘时现取，缓存字段会导致切语言后预览停在旧语言。
- **预览与真窗零参数偏差**：一切绘制参数从 `SubtitleStyle.of(mDraft, displayMetrics)` 取，绝不在 Activity 里另写一套字号/颜色/阴影换算。逐行 View + `stylePreviewLine()` = 真窗 `styleLine()` 的同一套参数（含模糊走同一个 `RenderEffect.createBlurEffect`）。允许的差异只有抗锯齿/栅格化。

### ④ 主字幕 / 活动行调整（6 参数 + 恢复默认）

| 行       | 控件                             | 范围               | 步长  | 默认             |
| ------- | ------------------------------ | ---------------- | --- | -------------- |
| 主字幕颜色   | 色板（8 预设 + 彩虹自定义环）              | 白/黑/绿/红/橙/青/紫/深蓝 | —   | 白 `0xFFFFFFFF` |
| 阴影颜色    | 同上（**同一张表**，用户不用记「第几行第几个是什么色」） | —                | —   | 黑 `0xFF000000` |
| 阴影强度    | 滑块                             | 0–100 %          | 5   | 50 %           |
| 阴影半径    | 滑块                             | 5–20 %           | 1   | 10 %           |
| 活动行不透明度 | 滑块                             | 50–100 %         | 5   | 100 %          |
| 放大倍数    | 滑块（×10 整数刻度）                   | 0.8–1.5 ×        | 0.1 | 1.0 ×          |

- 步长 5 而不是 1：1% 的差别肉眼不可辨，步长 5 让滑块更容易停在整十位。
- 放大倍数 / 行距一律走「整数刻度 × 10 或 × 2」，避免浮点步长在 Slider 上累积误差（0.5 累加十次 = 4.999999）。
- 末尾「恢复默认」= MD3 Tonal 胶囊按钮（↺ + 文字），下方常驻小字实时显示当前默认值。

### ⑤ 非活动行字幕调整（开关联动）

| 行      | 控件                     | 范围       | 默认   |
| ------ | ---------------------- | -------- | ---- |
| 模糊非活动行 | 开关                     | —        | 关    |
| 模糊半径   | 滑块（0–16 档，1 档 = 0.5px） | 0–8 px   | 3 px |
| 缩放非活动行 | 开关                     | —        | 关    |
| 缩放比例   | 滑块                     | 50–100 % | 90 % |

- **联动口径：关掉时滑块 `setVisibility(GONE)` 收回占位，不是置灰**（PRD FR-05 明确）。
- 模糊读数**直接显示 px**（`3.0px` / `7.5px`），不再显示「8 × 0.5px」这种算式。

### ⑥ 字幕排版

| 行          | 控件                             | 范围                  | 默认        |
| ---------- | ------------------------------ | ------------------- | --------- |
| 对齐         | 三段按钮（左/中/右）                    | —                   | 居中        |
| 字幕间行距      | 滑块（×2 刻度）                      | **−5 ~ +5 dp**（含负值） | 0         |
| 长字幕内换行额外行距 | 滑块（×2 刻度）                      | 0–5 dp              | 0         |
| 悬浮窗颜色      | 色板（**第一个是深蓝黑** `#0E1420`，不是纯黑） | 8 预设 + 自定义          | `#0E1420` |

- 行距允许负值（DK-02 拍板），所以滑块走 ×2 整数刻度而不是负起点。
- 悬浮窗颜色色板**必须把通用表里的「黑」换成「深蓝黑」**：两者视觉极近，同列会出现重复项，而 NFR-05 要求色板不能只靠颜色区分，重复色名就是 bug。
- 该行色板圆点画的是「面板**顶部**实际不透明度叠加后的效果」（≈57%，`PANEL_PREVIEW_TOP_ALPHA = 0x92`）+ 棋盘格衬底 —— 用户要能一眼看出「这个颜色会让面板透出后面的壁纸」，而不是看一个实心色块。
- 已删除的功能（配置键保留解析兼容，只是不再暴露）：**字重**（真机实测粗体不生效）、**保持屏幕常亮**（实测无效果）。

### ⑦ 其他

1. **状态栏字幕功能总闸**（`statusbar_subtitle_enabled`）+ **常驻**撤销权限提示小字
   - 🔴 **两级开关必须分清**：
     - **L1（本开关）= 插件级能力总闸**，持久配置，属于设置页。关 ⇒ ① 状态栏字幕停显 ② 播放页内那个开关按钮**消失** ③ 提示「本开关撤销不了已授予的 SystemUI 权限」
     - **L2（播放页那个开关）= 会话级**，状态存在**宿主侧**，只影响当前这次播放
     - ⚠️ **不要复用同一个字段表达 L2**：两者生命周期完全不同，且 L1 关时 L2 连 UI 都不存在
   - SystemUI 未授权 ⇒ **整行淡到 alpha 0.45 + 开关强制关**。但置灰时**只改 UI、不写 draft**：存储里的 true 表达「用户没主动关过」，与「现在没权限所以用不了」是两件事；用户之后去授权了，回到本页开关应自动恢复 true。
   - 切换时**不再弹 Toast**（2.3.1 §7.8 删除）——那条长提示本来就常驻在开关下方，再弹一次属于重复打扰。
2. **备份与恢复**：导出 / 导入两枚 MD3 Tonal 按钮，各带方向小图标，SAF（`CreateDocument` / `OpenDocument`）
   - 导入失败**三段提示**：非 JSON / 空文件 / 内容损坏，按异常与内容分支 toast
   - 导出文件名带版本号：`dlsitefloat-config-<versionName>.json`
   - v1.5 曾出现「导出/导入 位置一片空白」：根因是把 style 资源当 defStyleAttr 传给 MaterialButton，背景/字色都没落地 ⇒ 改为**显式给色调 + 禁用态**

### ⑧ 吸底操作栏

- 左「重启系统界面」= MD3 **tonal**（`colorSecondaryContainer` + `colorOnSecondaryContainer`），右「保存设置」= 填充主色（`colorPrimary` + `colorOnPrimary`）；各占一半宽、圆角 24dp、高 ≥48dp、无上沿分隔线
- **两枚 tint 必须显式写死**（`styleBottomBar()`）：`setBackgroundTintList()` 会**覆盖** XML 里的 `?attr/colorXxx` 引用，一旦写死动态取色/深浅色切换就再也不影响它。所以每次 `onConfigurationChanged` 重取一次色槽
- 「重启系统界面」走二次确认弹窗 → `ConfigBus.sendRestartSystemUi()`

## 三、横切设计逻辑（比单模块更重要）

### 3.1 草稿态 / 已保存态分离（PRD §9.1）

```
mSaved  = 磁盘现状
mDraft  = 界面绑定的唯一对象   ← 任何控件改动只写它
isDirty() = !mDraft.sameParametersAs(mSaved)   ← 派生值，不是标志位
```

- **「是否脏」是派生值**，不需要额外标志位与同步逻辑 ⇒ 改回去就自动不脏。
- `markDirty()` 统一收口：刷三个默认值小字 + 重绘预览。`mSyncing` 闸门拦住程序性赋值，否则「一切换语言就变成脏」。
- **语言被排除在「脏」之外**：语言只影响设置页 UI 与预览示例字幕，对悬浮窗毫无影响。若算进「脏」，用户只是切个语言再返回就会被弹「有未保存的更改」三选——那对话框是给外观改动用的。
  - 实现口径：**临时把两侧 `uiLanguage` 对齐再比**，而不是改 `sameParametersAs()`（那个方法在别处也用于「配置无变化」判定，改它会污染别处的判断）。
  - 切语言**立即独立保存**（`saveUiLanguageOnly`，只写设置页自己的 MODE_PRIVATE prefs，不发广播、不覆盖其他参数）。
  - ⚠️ 顺序：**先独立保存、再改 mDraft**。反过来会出现「保存后语言又变回去」。
- 返回时三选：保存（失败则留在页面、草稿不丢）/ 不保存（`mDraft = mSaved.copy()`）/ 取消。

### 3.2 行构建：全部用代码，不用 XML

四个 `addXxxRow` 原语（`SliderRow` / `SwitchRow` / `SegmentedRow` / `ColorSwatchRow`）覆盖全部 20 余行。理由：

1. 行形态统一（标签 + 控件 + 小字），代码构建比二十多份 XML 更省维护；
2. 「控件 ↔ 配置键」的映射集中在一处可见。

**视觉常量收敛**（2.3.x §7.1.1「四个卡片内上下边距有视觉差距」的解法）：

| 常量                       | 值      | 作用                                   |
| ------------------------ | ------ | ------------------------------------ |
| `CARD_PAD_TOP/BOTTOM_DP` | 6 / 6  | 卡片内上下留白，统一到「字幕排版」卡片的口径               |
| `ROW_GAP_DP`             | 4      | 行间 / 分隔线上下的呼吸位                       |
| `ROW_MIN_H_DP`           | **40** | 所有行统一最小高度并垂直居中                       |
| `CONTROL_H_DP`           | 40     | 行内控件（按钮/开关）统一高度                      |
| `HINT_BOTTOM_PAD_DP`     | 0      | 小字底距交给卡片 paddingBottom 收口（相加会变 12dp） |

- `ROW_MIN_H_DP = 40` 是解决「四张卡片首行文字起始位置各不相同」的关键：v1.5 行高是被内容撑开的，开关行被 32dp 的 MaterialSwitch 撑高、文字被垂直居中推低 6dp，分段行只有文字、顶边就是行顶边。钉死统一最小高度后，「首行文字顶边」在任何卡片里都等于同一值。
- `beginRow()`：**非首行**先插一根 1dp `colorOutlineVariant` 细分隔线（上下各 4dp 呼吸位）。首行不能插，否则卡片顶边出现悬空的线。⇒ 参考 KernelSU 的「一张卡里若干行、行间极细分隔」，而不是 v1.5 的「一坨没有界限的行」。

### 3.3 三处「样式资源不能当 defStyleAttr 传」

同一个根因踩了三次，统一记账：

| 控件                                | 症状                            | 修法                                                                                                                                                                              |
| --------------------------------- | ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 分段按钮（`MaterialButtonToggleGroup`） | 三段全同色，选中态看不出来 ⇒ Ari 判成「点选不可用」 | 弃用 ToggleGroup，改普通 MaterialButton + `paintSegments()` 自己画（选中 = `colorSecondaryContainer` 底 + `colorOnSecondaryContainer` 字，未选中 = 透明底 + `colorPrimary` 字；**「有底 vs 没底」** 深浅模式都成立） |
| 色板 / 重置 / 导出导入小按钮                 | 深底压黑字、整页禁用时按钮消失               | `makeTonalButton()` / `styleTonalButton()` 显式给 `backgroundTint` + 文字色 + 禁用态                                                                                                     |
| 语言胶囊                              | 只画出图标，文字被吃                    | 拆成两个兄弟 View                                                                                                                                                                     |

### 3.4 配色分层（KernelSU 质感）

| 表面                                | 浅色                                   | 夜间                                    |
| --------------------------------- | ------------------------------------ | ------------------------------------- |
| 页面大底（根布局 / 吸顶区 / 吸底栏 / 状态栏 / 导航栏） | `colorSurface` 奶白 `#FDF8F6`          | `colorSurfaceContainerLow` `#211F26`  |
| 分组卡片                              | `colorSurfaceContainerLow` `#F7F2FA` | `colorSurfaceContainerHigh` `#36343D` |

- **夜间整体上抬一档**：MD3 的 `colorSurface` 在暗色下极暗（动态取色时约 `#131316`），ARI 反馈「夜间背景还是太黑」；而卡片只比它亮 5 档 ⇒「卡片也没有底色」。上抬后底 ≈ `#211F26`、卡片 ≈ `#36343D`，两者都提亮且对比拉到 10 档。
- **吸顶区必须与页面大底逐字节同色**（`applyPageBackground()` 把三个容器绑到同一个值）：只要有一点差异，钉住的那条就会在左右两侧显出「另一种底色」。状态栏 = 大底色，**不染色**（不是 `colorPrimary`、也不是 MD2 的 `colorPrimaryDark`）。
- **禁止硬编码十六进制**，一律引用色槽（`?attr/colorXxx`），否则动态取色（Android 12+ Tonal Spot）会把页面留在旧色上。唯二例外是色板预设与兜底色——那是**配置数据**。
- 主题 = `Theme.Material3.DayNight.NoActionBar`，自动跟随系统深浅，不做手动模式切换。

### 3.5 显示尺寸钉死（NFR-03）


- `fontScale = 1.0f` **无条件钉死**；`densityDpi` **读到才钉**（读 `Settings.Secure` 的 `display_density_forced`，默认档位下这个键往往不存在）。
  - 读不到 ⇒ **有意保留的降级**：页面等比缩放、字号也变，但行形态是代码构建的流式布局，最坏只是换行多一点，不会像绝对定位那样错位。
- 必须用 `applyOverrideConfiguration()` 而不是 `createConfigurationContext()`：后者只钉住子 Context，**Activity 自己的 Resources 仍继承 BaseContext 的 metrics** ⇒ 实测「显示大小」拉大后整页仍等比放大、语言胶囊被撑宽溢出。部分 ROM（ColorOS）还会忽略传入的 `densityDpi`，把 density/scaledDensity 算成另一套值 ⇒ dp→px 与 sp→px 脱节。
- 必须在 `super.attachBaseContext()` **之前**调用（之后会抛 `Resources already created`）；之后还要 `applyPinnedMetrics()` 再钉一次 DisplayMetrics，覆盖个别 ROM 的「覆盖它的覆盖」。
